# azure-apim-emulator v0.2.0

A security fix worth taking, a default that now matches the rest of the family,
and a large increase in how much of this emulator's parity ledger is proved by
somebody else's code rather than our own.

## Security: SSRF on linked API import

`openapi-link` import fetches an operator-supplied URL, which is a first-class
APIM feature and therefore a first-class server-side request forgery surface.
Two guards now sit in front of it:

- **Before the fetch**, the host is rejected if it resolves to link-local or
  metadata (`169.254.169.254`, `fe80::/10`), multicast, or unspecified
  addresses. Loopback and private hosts stay allowed, because importing from a
  service on the developer's own machine is the point of a local emulator.
- **At connect time**, a `net.Dialer.Control` hook re-validates the resolved IP
  immediately before the socket opens. The pre-fetch check alone is not enough:
  DNS can rebind between the check and the dial, and a name that passed the
  first guard can point at the metadata endpoint by the time it is dialled.

Upgrade if you accept import URLs from anywhere you do not fully control.

## `./data` is the default, and empty still means in-memory

An unset `APIM_DATA_DIR` now means `./data`, matching entra, arm and keyvault.
An **explicitly empty** value still means in-memory, which is what the compose
files use so a throwaway stack leaves no volume behind. If you relied on unset
meaning in-memory, set it to empty explicitly.

## Evidence: 2 of 25 green claims independently evidenced, now 22 of 25

`internal/server/sdk_test.go` drives 23 `armapimanagement` clients through
Microsoft's own Go SDK, and the parity ledger described that evidence row by
row, but `docs/witnesses.json` cited it once. The other 23 rows cited this
repo's own store and handler tests, so the ledger understated itself badly.

Relabelling all 23 onto one test name would have been worse than the low
number, because a single witness covering 23 claims is the bundling the witness
gate exists to expose. So the test was split first, into 26 named subtests, one
per resource family. The change is mechanical: `git diff -w` shows only hoisted
client construction and the declarations that cross a subtest boundary, with no
assertion altered, and the suite still runs in 0.08s.

- The witness checker resolves subtest names, so `sdk:TestX/tag` is verified
  against the tree like any other witness rather than taken on trust.
- It also prints a report when any witness carries more than three claims.
  Nothing does now.
- Policy fragments additionally cite `ci:sdk-witnesses`, which the JavaScript
  SDK witness covers in eight calls.

The three rows still resting on this repo's own tests are honest ones: no
external client covers the operator portal, WebSocket/SSE tunnelling, or
process/config/TLS/store/clock.

## Running it

- `make up`, `make status`, `make down`, `make doctor`. `status` probes the
  seam rather than liveness: entra discovery, apim health, and a management
  call correctly refused without a token.
- The witness suites run on Windows, and every recipe is exercised in CI on
  Linux, macOS and Windows before a release.
- `e2e/javascript` joined the pnpm workspace; SDK setup goes through pnpm and
  uv.

## Upgrading

Pull `0.2.0`. The only behaviour change is the data directory default above;
the ARM and gateway surfaces are unchanged.
