# azure-apim-emulator v0.3.0

The P2 expression bottleneck and a batch of leftover P1 gateway/policy work —
honestly labelled. The parity ledger
([docs/parity.md](https://github.com/calvinchengx/azure-apim-emulator/blob/main/docs/parity.md))
still grades C# expressions **partial** and several policy families **partial**;
Azure differential fixtures remain pending an authorized live run. What shipped
here is local, witnessed, and CI-gated at 100% statement coverage.

## C# expression engine (P2)

A pure-Go evaluator now drives APIM policy expressions end to end:

- **Value model and lexer** with .NET operator semantics, `@(expression)` and
  `@{block}` wrappers, and `\u` escapes as 16-bit code units.
- **`context` binder** for request/response URL, headers (`Get`, indexer,
  `GetValueOrDefault`), `Url.Port`, `Body.AsString()` with capture/replay,
  response status/headers, `LastError.Message`, variables, and snapshot-backed
  `Api` / `Operation` / `Product` / `Subscription` / `User` / `Deployment`
  scalars.
- **Statement blocks** with expression-scoped `var` locals, `if`/`else`, and a
  required `return` on every path.
- **Policy fields** wired through `compileValue` / `evalValue` across mutation,
  CORS, `check-header`, limits, authentication, `set-status`, `mock-response`,
  transforms, cache, `send-request`, retry conditions, and more.
- **Binder allowlist** checked in at `docs/generated/expression-members.json`
  with a table test so new host members cannot land unbound.

Still fail-closed: `LastError.Reason`, `Body.AsJObject`/`AsJson`, loops, `new`,
LINQ, and the rest of the documented .NET surface.

## Policy inventory and governance

- The Microsoft Learn policy catalog is fully classified (`implemented` /
  `partial` / `unsupported` / `external-adapter`); CI rejects `unclassified`
  names and compiler drift (`scripts/check_policy_inventory.py --strict`).

## Gateway and policy (leftover P1)

- **Nested `rate-limit` / `quota`** `api`/`operation` children and quota
  `bandwidth`; first-class sequential **`wait`** under `limit-concurrency` and
  `retry`.
- **`validate-jwt`** enforces audiences, issuers, and required claims from the
  payload; **`validate-azure-ad-token`** adds `client-application-ids` and
  required claims (`openid-config` and inline `token-value` stay unsupported).
- **`mock-response`** example bodies; product subscription composition uses the
  **matching operation plan**; ARM GET/PUT for service/API/operation/product
  policies.
- **Key Vault**: 401 `WWW-Authenticate` Bearer challenge acquires a
  managed-identity token and retries once; last-known-good on failure.
- **Diagnostics**: request/response body capture via ARM
  `frontend.*.body.bytes` limits (hard-capped at 8192) with the same secret
  masking as headers.

## Running it

Same family workflow: `make up`, `make status`, `make down`, `make doctor`.
Every recipe runs on Linux, macOS, and Windows before release.

## Upgrading

Pull `0.3.0`. No deliberate breaking changes to ARM or gateway contracts.
Policies that previously failed at compile time because expressions were
unsupported may now evaluate — review XML that relied on fail-closed behavior.
Unset `APIM_DATA_DIR` still defaults to `./data` (since v0.2.0).

## Known boundaries at v0.3.0

- C# expression parity row remains **partial** (no Azure differential corpus).
- Many policy families are classified but not implemented; workspace scope
  inheritance is open.
- `wait` is sequential, not parallel; subscription-scoped rate counters remain
  partial.
- External diagnostic sinks, full Azure Monitor schema, and authorized
  `make test-differential` are still tracked work.
