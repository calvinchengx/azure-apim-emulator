# azure-apim-emulator v0.4.0

Eight of the ten capabilities flagged as important, the P5 protocol families,
and a rebuilt expression engine. Also the first release that can be **measured
against Microsoft's published surface** rather than only against rows this
project chose to write.

The parity ledger
([docs/parity.md](https://github.com/calvinchengx/azure-apim-emulator/blob/main/docs/parity.md))
grades 33 rows `implemented`, 2 `sdk-verified`, 14 `partial` and 3 `planned`.
Nothing is graded `verified`: **no claim here has been diffed against Azure
itself**, and the ledger names what each one does rest on.

## The published operation surface, measured

All **611** operations Microsoft publishes for stable `2024-05-01` are
enumerated from a pinned spec commit and probed against a fresh service each:
**367 routed, 124 absent, 120 unmeasured**
(`docs/generated/operation-coverage-2024-05-01.json`).

`routed` means an operation answers something other than 404. It proves the
operation exists and says nothing about whether its behaviour is right, so it
is a floor under the surface rather than a parity claim. `unmeasured` is the
honest remainder: a 404 the harness cannot attribute to a missing route rather
than a missing parent.

## Protocols (P5)

- **GraphQL**: pass-through with gateway-side validation and introspection,
  plus synthetic resolvers over `<http-data-source>`. Witnessed by the
  reference `graphql` implementation on both ends.
- **gRPC**: unary and server-streaming pass-through over real HTTP/2,
  witnessed by `grpc-js` as both client and server. This required enabling
  HTTP/2 on **both** legs; the emulator had served HTTP/1.1 only.
- **SOAP**: pass-through with WSDL import, witnessed by the `soap` package.

Client and bidirectional streaming, gRPC-Web, and SOAP-to-REST remain open.

## Workspaces, RBAC and link resources (P4)

- **Workspaces as a scope**, not a resource kind: the router peels
  `/workspaces/{id}` and every family below is available inside it unchanged.
- **Azure RBAC** role assignments with Azure's evaluation model, enforcement
  opt-in behind `APIM_ENFORCE_RBAC`.
- **Link resources** (`productApiLinks`, `productGroupLinks`, `tagApiLinks`,
  `tagOperationLinks`, `tagProductLinks`) at both service and workspace scope.
  They project the associations the emulator already stored rather than
  duplicating them, so the older `products/{id}/apis/{apiId}` spelling and the
  link spelling can never disagree.

## Credential manager, gateways, platform (P6/P7)

- **Authorization providers** with the authorization-code and
  client-credentials grants, witnessed against a real OAuth2 authorization
  server. `get-authorization-context` withholds the refresh token from
  policies, which is the point of a credential manager.
- **Self-hosted gateways** with registration, keys, hostname routing and
  per-gateway CA trust. The container's configuration-sync payload is
  proprietary and uncaptured, so no real self-hosted gateway has connected to
  this emulator and none is emulated.
- **Tiers, SKUs and regions**, with capability gating opt-in behind
  `APIM_ENFORCE_TIERS`. **The default is more permissive than a tenant**, which
  is a deliberate trade and is stated in the ledger.
- **Networking**: private endpoint connections, network status, custom-domain
  certificate state and mTLS hostnames. Private connectivity itself is not
  emulated.

## AI gateway and MCP (P8)

- `llm-token-limit` and `llm-emit-token-metric` under both the `llm-*` and
  `azure-openai-*` names, counting streamed answers by teeing the write path.
- **An API published as an MCP server**, its operations exposed as tools, plus
  passthrough to an upstream MCP server. Witnessed by OpenAI's own client and
  by `@modelcontextprotocol/sdk`.

Token arithmetic is exact from the model's `usage` and approximate under
`estimate-prompt-tokens="true"`.

## Expressions (P2)

The documented `context` surface is now derived from Microsoft's own sources
rather than transcribed, and gated against drift. **127 members bound**, 26
still planned, with the framework surface tracked separately.

Landed here: interpolated strings, lambdas and `Any`, null-conditional access
and null-coalescing, assignment and fall-through branches, typed locals, `new`
for `Random`/`Uri`/`JObject`/anonymous objects, the `System.String` members, the
JWT cluster, `DateTime`/`DateTimeOffset`/`Guid`, and variables that hold objects
rather than only their rendering. The parser is gated against Microsoft's own
policy corpus.

## Documentation

First release with **quickstart, installation and configuration** pages. Every
`APIM_*` variable is now documented; twelve of sixteen previously appeared
nowhere. Design chapters were renumbered to match the family's shared scheme, so
chapter URLs have moved.

## Fixes worth naming

- `authorizationProviders` 404'd at workspace scope, and service-only families
  were served there when Azure does not expose them.
- Header indexing returned the first value of a set rather than the values.
- A gRPC trailer assertion was flaky because `Header().Get()` reads one value
  from a map-ordered set.
- CI ran twice per pull request.

## Known limitation carried forward

Images from 0.3.0 and earlier report their version as `dev`. Fixed here: the
image and the tarball from this tag report the identical string.
