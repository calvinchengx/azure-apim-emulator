# azure-apim-emulator v0.1.0

The first release: a clean-room, local emulator of Azure API Management's
publicly observable behavior — management plane, gateway, and policies — that
joins the emulator family. entra-emulator issues its tokens; the family BOM in
[azure-emulators](https://github.com/calvinchengx/azure-emulators) certifies
the combination.

This is the P0/P1 vertical slice, honestly labelled: the parity ledger
([docs/parity.md](https://github.com/calvinchengx/azure-apim-emulator/blob/main/docs/parity.md)) grades every capability track, and Azure
differential fixtures for exact wire wording are still pending an authorized
live run. What is here is witnessed by Microsoft's own management SDKs — Go
`v1.1.1`, JavaScript `10.0.0`, Python `5.0.0`, .NET `1.3.1` — each running a
configure-service → protected-API → subscription → call-through-the-gateway
workflow in CI, including a real `azidentity.ClientSecretCredential` flow
through entra-emulator.

## Management plane (ARM, api-version `2024-05-01`)

- Service GET/PUT/PATCH/DELETE/list with lossless schemas and deterministic
  LRO polling.
- APIs, operations, revisions (with cloning), version sets, releases,
  products and links, groups and memberships, users (CRUD/SSO/tokens),
  subscriptions with key regeneration, named values, backends, PFX
  certificates, policy fragments (recursive gateway expansion,
  cycle/missing-reference validation), loggers, diagnostics, tags.
- **ARM conditional requests**: strong/weak ETags, `If-Match`/`If-None-Match`,
  atomic mutation checks, `412 PreconditionFailed` witnessed by the Go SDK.
- **ARM collection queries**: stable paging with query-preserving `nextLink`,
  OData filter grammar (comparison/logical/string functions,
  `tags/any(...)`/`tags/all(...)`), ordering, exact failure coverage.
- The canonical **ARM error envelope** (`x-ms-error-code`, details,
  request/correlation IDs), witnessed via the Go SDK's `ResponseError`.

## Gateway

- Operation-template routing, subscription keys, custom hosts.
- Streaming backend forwarding with TLS validation and client certificates,
  retry policies with body replay, persisted circuit-breaker rules, SSE.
- Policy XML compilation and execution: `base`, `set-header`,
  `set-backend-service`, `rewrite-uri`, `forward-request`, `return-response`,
  CORS (responses and preflight), query/variable/body/method mutations.
- Immutable gateway snapshots: config changes take effect the way APIM
  deployments do, not mid-request.

## Runs like the family

Static Go binary on distroless (nonroot, writable `/data` volume, healthcheck
subcommand), pure-Go SQLite, controllable clock, local TLS. Multi-arch GHCR
image published from this release. Realistic opaque GUIDs for seed data, per
the family convention.

- **`make up` / `status` / `down` / `doctor`**, over a compose pair that pulls
  entra pinned and builds apim *from source* — the everyday cycle tests the
  checkout, not the last thing GoReleaser shipped. `status` probes the seam:
  entra discovery, apim health, and a management call refused without a token.
  A cross-OS `make-targets` job expands every recipe on Linux, macOS and
  Windows, and gates the release.
- **Green parity claims are machine-checked.** Every row the ledger grades
  `implemented` or `sdk-verified` names its witness in
  [`docs/witnesses.json`](https://github.com/calvinchengx/azure-apim-emulator/blob/main/docs/witnesses.json), and CI fails if a witness stops
  existing — 25 claims, 51 witnesses at this tag. Rows graded *partial* or
  *planned* are exempt; they claim nothing yet.
- pnpm for all JavaScript (docs site and the SDK witness), uv for Python.

**In the family BOM.** [azure-emulators](https://github.com/calvinchengx/azure-emulators)
certifies this release alongside entra 0.4.1, arm 0.2.0, keyvault 0.6.0 and
fabric 0.19.0: its chain test stands the stack up and asserts apim accepts an
entra-minted ARM-audience token and refuses a foreign-issuer one. Run it with
`docker compose --profile apim up`.

## Known boundaries at v0.1.0

- Key Vault named-value retrieval and the broader resource inventory are
  pending (see the ledger's target phases).
- Differential fixtures against live Azure are prepared but not yet run under
  authorization; parity wording claims are scoped accordingly.
- Developer portal workflows are partial (tag/certificate/group/subscription/
  user editors landed; more tracked in the ledger).
