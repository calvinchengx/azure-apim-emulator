# azure-apim-emulator v0.5.0

Throttling that counts the right thing, JWT validation that honours the
attributes it advertises, and a policy compiler that refuses a policy in a
section Microsoft's reference does not document.

This release does not widen the surface. It deepens it, and most of what it
contains is a **correction**: policies the previous release already accepted
were doing something other than what their reference page describes. The
ledger grades are unchanged for exactly that reason.

The parity ledger
([docs/parity.md](https://github.com/calvinchengx/azure-apim-emulator/blob/main/docs/parity.md))
grades 33 rows `implemented`, 2 `sdk-verified`, 14 `partial` and 3 `planned`,
the same as v0.4.0. Nothing is graded `verified`: **no claim here has been
diffed against Azure itself**, and the ledger names what each one does rest on.

The published operation surface is also unchanged at **367 routed, 124 absent,
120 unmeasured** of the 611 operations Microsoft declares for stable
`2024-05-01`. This release changed behaviour behind routes that already
answered, which that measurement cannot see.

## Rate limiting and quota, corrected (#111, #115, #116, #117, #121)

The largest correction in the release, and none of it was visible as a failing
test, because the tests asserted the emulator's own behaviour.

- **`rate-limit` and `quota` counted in ONE GLOBAL BUCKET**, so one caller
  throttled another, and both applied with no subscription key at all.
  Counting is now per subscription, and `counter-key` is rejected on the
  keyless variants, which Azure does not accept.
- **A nested `<api>` limit throttled unrelated APIs.** Limits are now scoped to
  the API they are declared under, and the documented period bounds are
  enforced rather than accepted silently.
- **A quota window never reset.** Quota now counts in a fixed window anchored
  by UTC truncation per period, and an infinite period is allowed.
- **The counters were invisible.** `remaining-calls-header`,
  `remaining-calls-variable`, `total-calls-header` and
  `retry-after-variable` are honoured, and `Retry-After` reports the real
  remaining window rather than a constant.
- **`increment-condition` and `increment-count`** are honoured, including the
  postponed increment.

The attribute surface these policies accept is now **derived from Microsoft's
reference pages** at a pinned commit rather than transcribed (#112), and a
check gates the derivation. Two policies were previously graded `implemented`
while ignoring six documented attributes each.

## Authentication (#124, #125)

- **`validate-jwt` with `openid-config`**: discovery is fetched and cached for
  an hour, with a rate-limited refresh on a `kid` miss. This exposed a second
  defect it now also fixes: **an expired token was accepted**, because the
  lifetime was never checked.
- `require-scheme`, `require-signed-tokens` and `output-token-variable-name`
  are honoured rather than parsed and dropped.

## AI gateway (#126)

`llm-token-quota`, and the dimension cap that `llm-emit-token-metric` was
missing. A quota-only LLM policy is no longer refused outright.

## The policy compiler (#127, #106, #123)

- **A policy in a section its reference page does not document is now
  rejected.** The `sections` field of the policy inventory had been
  hand-written and was **wrong for 28 of 70 entries**, including the whole
  authentication family. It is derived and enforced now.
- **Named arguments**, with the names taken from Microsoft's published
  signatures rather than chosen here.
- C# member names stay capitalised, because case-sensitivity is what a tenant
  actually enforces.

## Witnessing (#108)

The ARM document families are witnessed by Microsoft's **packaged**
`@azure/arm-apimanagement` running over the network, not only by an in-process
Go client. A witness that builds its own requests tests the contract you
believe in; only a real client tests the one the ecosystem sends.

## Supply chain and CI (#105, #109, #119, #122, #143, #144)

Secret and vulnerability scanning with named findings and job timeouts,
`gofmt` enforced, and `golangci-lint` at zero findings. Five npm advisories
were closed (`fast-uri`, `@xmldom/xmldom`, `qs`); all three are transitive
dependencies of the **end-to-end witness harnesses and the docs site**, not of
the shipped Go binary, which carries no npm dependency at all.

## Documentation

The site publishes a landing page at `/` with the docs beneath it at `/docs/`,
and every headline number on that page is read from a manifest at build time,
with a check that fails the build on a typed one.

Two things there are worth naming because they were live defects:

- **Every URL the docs site had ever published was returning 404** after the
  base moved. `website/published-routes.txt` is the route list captured from
  the build immediately before that move, and the assembler writes a redirect
  stub for every entry and fails the deploy if any would 404.
- **Every page requested a favicon that was never shipped.** The assembler now
  resolves every absolute reference in every built page, and fails if the
  check stops matching anything at all.

`make docs-build` and `make docs-serve` build and serve the assembled site at
the paths it publishes under. CI runs the same target, so the preview and the
deploy cannot drift.

## Known limitations carried forward

- Nothing is graded `verified`. The differential harness against a real tenant
  exists (`e2e/differential`) but has never run.
- Token arithmetic is exact from the model's `usage` and only approximate
  under `estimate-prompt-tokens="true"`.
- The expression language has no lambdas, so LINQ over the bound collections
  is unavailable, and says so rather than returning false.
- `Body.As<T>()` and `AsFormUrlEncodedContent` need generic call syntax the
  parser does not have.
